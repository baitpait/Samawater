# تحليل استيراد بيانات Excel (سما عام.xlsx)

**التاريخ:** 2026-01-29  
**الملف:** سما عام.xlsx  
**الحالة:** تحليل فقط — لا تنفيذ حتى تقول «تم».

---

## 1. الشيت المستخدم

- **المتفق:** استيراد من شيت **«الاشتراك»** (sheet2).
- الشيت الأول «من الى» = حركات مالية فقط، ولا يُستورد منه مشتركين.

---

## 2. تحليل قاعدة البيانات (قبل البدء)

### 2.1 الجداول المستخدمة في الاستيراد

| الجدول | الأعمدة المستخدمة | ملاحظة |
|--------|-------------------|--------|
| **cities** | id, city_name | المدن من **عمود G** (أسماء المدن)؛ تُدخل إن لم تكن موجودة وتُربط بـ city_id. |
| **subscription_types** | id, type_name, distribution_days | حالياً: يومي، أسبوعي، نصف شهري، شهري. سنضيف **محدود** و **غير محدود** ونربط عمود C بهما. |
| **subscription_statuses** | id, status_name | حالياً: نشط، متوقف، ملغي. عند الاستيراد نربط الجميع بـ «نشط» ما لم تُحدد غير ذلك. |
| **client_types** | id, type_name | إضافة **فردي** إن لم يكن موجوداً. كل مشترك مستورد يُربط به (نوع المشترك = فردي). |
| **clients** | name, city_id, address, phone_one, phone_two, **client_type**, subscription_type_id, subscription_status_id, subscription_start_date, notes, **bottle_balance** | انظر الخريطة أدناه. |

### 2.3 المتطلبات الجديدة (المدمجة في التحليل)

| المطلوب | التطبيق في الاستيراد |
|---------|------------------------|
| **نوع المشترك** | إضافة **فردي** إلى جدول `client_types` إن لزم، وربط كل مشترك مستورد به (`client_type` = فردي). |
| **حالة الاشتراك** | ربط كل مشترك بـ **نشط** من جدول `subscription_statuses` (`subscription_status_id` = نشط). |
| **مجموع العبوات** (عمود في Excel) | تعيينه إلى **رصيد القوارير** → `clients.bottle_balance` (العمود **M** في الشيت). |
| **مطلوب ش** (عمود في Excel) | إضافته إلى **ملاحظات العميل** → يُدمج مع B و I و G في `clients.notes` (العمود **L** في الشيت). |

---

### 2.2 مصدر المدن في الإكسل

- **عمود G** في الشيت = **أسماء المدن**.
- القيمة في G تُستخدم مباشرة كاسم المدينة؛ إن وُجدت تُدخل في جدول `cities` (إن لم تكن موجودة) ثم يُربط العميل بـ `city_id`. إن كانت G فارغة يُترك `city_id` فارغاً.

## 3. بنية شيت «الاشتراك» (sheet2)

- **صف الهيدر:** الصف 3.
- **أول صف بيانات:** الصف 4.
- **عدد الصفوف التي فيها اسم مشترك (عمود K):** **257** مشترك.
- **عدد الصفوف التي فيها أي بيانات (B أو K):** **257**.

### أعمدة الهيدر (الصف 3) — وما نستورده

| العمود | اسم الهيدر  | الاستخدام في الاستيراد |
|--------|-------------|-------------------------|
| A      | (فارغ)     | — |
| **B**  | **الادوات**| → نضعها في **ملاحظات العميل** (مع ملاحظة و L إن وُجدت). |
| **C**  | **الاشتراك**| → **نوع الاشتراك**: محدود / غير محدود (وقيم أخرى مثل «كولر ميجا» — انظر الفقرة 4). |
| D      | الاحداثيات | يمكن تجاهله أو حفظه في الملاحظات إن أردت لاحقاً. |
| **E**  | **هاتف**   | → **هاتف العميل (الرقم الأول)** = `phone_one`. |
| **F**  | **هاتف3**  | → **الهاتف الثاني** = `phone_two`. |
| **G**  | **المدينة / أسماء المدن**| → **المدينة** = `city_id` (من جدول `cities`، أولاً أو إنشاء). |
| **H**  | **العنوان**| → **عنوان المشترك** = `address`. |
| **I**  | **ملاحظة** | → نضمّنها في **ملاحظات العميل** = `notes`. |
| J      | (فارغ)     | — |
| **K**  | **اسم المشترك**| → **اسم المشترك** = `name` (واستخراج المدينة إن وُجد نمط "مدينة - ..."). |
| **L**  | **مطلوب ش**   | → نُضاف إلى **ملاحظات العميل** (مع B و I و G). |
| **M**  | **مجموع العبوات**| → **رصيد القوارير** = `clients.bottle_balance`. |

**ملاحظة:** مواقع الأعمدة (L، M، إلخ) قد تختلف حسب دمج خلايا في الشيت؛ عند التنفيذ يُحدد عمودا «مطلوب ش» و «مجموع العبوات» بالبحث عن نصوص الهيدر في الصف 3.

باقي الأعمدة (N فما بعد) = تواريخ ودفعات — لا نستوردها في مرحلة العميل الأساسية.

## 3. التطابق مع قاعدة البيانات (جدول `clients`)

الحقول المطلوبة للاستيراد (بما فيها المتطلبات الجديدة):

| حقل في النظام        | مصدره من Excel / القيمة الثابتة     | ملاحظة |
|----------------------|--------------------------------------|--------|
| **name**             | عمود **K** (اسم المشترك)             | كما هو دون استخراج مدينة من النص. |
| **city_id**          | عمود **G** (أسماء المدن)             | اسم المدينة من G؛ أولاً أو إنشاء في `cities` ثم الربط. |
| **address**          | عمود **H** (العنوان)                 | |
| **phone_one**        | عمود **E** (هاتف)                    | |
| **phone_two**        | عمود **F** (هاتف3)                   | الهاتف الثاني. |
| **notes**            | أعمدة **B + I + L**                   | الأدوات + ملاحظة + **مطلوب ش (L)** في ملاحظات العميل (G = المدينة، لا يُدمج في الملاحظات). |
| **bottle_balance**   | عمود **M** (مجموع العبوات)          | **رصيد القوارير** — القيمة الرقمية من M. |
| **client_type**      | **ثابت: فردي**                      | إضافة «فردي» إلى جدول `client_types` إن لزم، وربط كل مشترك مستورد به. |
| **subscription_status_id** | **ثابت: نشط**              | ربط كل مشترك بحالة الاشتراك «نشط» من جدول `subscription_statuses`. |
| **subscription_type_id** | عمود **C** (الاشتراك)            | محدود / غير محدود (وإنشاء النوعين في `subscription_types`). |
| **subscription_start_date** | **تاريخ اليوم**               | لا يُؤخذ من الملف. |

حقول تُترك فارغة أو افتراضية عند الاستيراد: `contract_no`, `city_id` (يُملأ من استخراج المدينة)، `distributor_id`, `delivery_on_demand`, إلخ.

## 4. نوع الاشتراك: محدود / غير محدود (+ كولر ميجا)

في عمود **C (الاشتراك)** ظهرت القيم التالية في الملف:

- **محدود**
- **غير محدود**
- **كولر ميجا**

في قاعدة البيانات جدول **`subscription_types`** فيه حالياً (من الـ seed): **يومي، أسبوعي، نصف شهري، شهري** (مع `distribution_days`).

الخطة المقترحة:

1. **إضافة نوعي اشتراك جديدين** في `subscription_types`:
   - **محدود** (وضع `distribution_days` حسب سياستك، مثلاً 30 أو قيمة ثابتة).
   - **غير محدود** (مثلاً `distribution_days = 0` أو 365 حسب منطقك).
2. **تعيين الصفوف:**
   - إذا كانت C = «محدود» → نربط العميل بـ نوع الاشتراك «محدود».
   - إذا كانت C = «غير محدود» → نربط العميل بـ نوع الاشتراك «غير محدود».
   - إذا كانت C = «كولر ميجا» (أو أي قيمة أخرى): إما نربطها بأحد النوعين (مثلاً «غير محدود») أو نترك `subscription_type_id` فارغاً ونضع النص في `notes` — نحدد ذلك عند التنفيذ حسب تفضيلك.

## 6. مثال واحد للاعتماد عليه (قبل البدء)

**صف 59 من شيت «الاشتراك»** — كما في الملف:

| العمود | القيمة في الملف |
|--------|------------------|
| B (الادوات) | (قيمة إن وُجدت) |
| C (الاشتراك) | محدود / غير محدود / كولر ميجا |
| E (هاتف) | — |
| F (هاتف3) | — |
| G | — |
| H (العنوان) | 13+25 |
| I (ملاحظة) | — |
| **L (مطلوب ش)** | (قيمة إن وُجدت، تُضاف إلى الملاحظات) |
| **M (مجموع العبوات)** | (رقم، مثلاً 6 أو 8) → رصيد القوارير |
| K (اسم المشترك) | **الخليل - واد الهرية -مصنع عبد شاكر** |

**ما سيحدث عند الاستيراد (مثال اعتماد):**

1. **جدول `cities`**  
   - اسم المدينة من **عمود G** (إن وُجد). إن لم تكن المدينة موجودة → إدخالها ثم أخذ `id`؛ وإلا استخدام `id` المدينة الموجودة.

2. **جدول `client_types`**  
   - إن لم يكن «فردي» موجوداً → إدخاله.  
   - ربط المشترك بنوع **فردي** (`client_type` = فردي أو id النوع حسب تصميم التطبيق).

3. **جدول `subscription_types`**  
   - إن كانت C = "محدود" أو "غير محدود" والنوع غير موجود → إدخاله ثم الربط.  
   - ربط المشترك بـ `subscription_type_id` المناسب.

4. **جدول `subscription_statuses`**  
   - ربط المشترك بحالة **نشط** (`subscription_status_id` = id «نشط»).

5. **جدول `clients`** — سجل واحد:
   - `name` = من عمود K (اسم المشترك) كما هو.
   - `city_id` = من عمود G (اسم المدينة)، إن وُجد.
   - `address` = **13+25** (من H).
   - `phone_one` = من E، `phone_two` = من F.
   - **`notes`** = دمج **B + I + G + L (مطلوب ش)**.
   - **`bottle_balance`** = القيمة من **M (مجموع العبوات)** (رصيد القوارير).
   - **`client_type`** = **فردي**.
   - **`subscription_status_id`** = id **نشط**.
   - `subscription_type_id` = حسب C.
   - `subscription_start_date` = **تاريخ اليوم**.

نفس المنطق يُطبَّق على كل الصفوف المستوردة.
